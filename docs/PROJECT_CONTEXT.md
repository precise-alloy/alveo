## Error handling

Pure `*-core` modules receive injected loggers (`log` / `logMissing`) and return result objects
(e.g. `{ missing: [] }`) instead of throwing across boundaries. The CLI reports failures with
`[alveo]`-prefixed `console.error` and sets `process.exitCode = 1` rather than hard-exiting
mid-pipeline. SSR render paths wrap rendering in try/catch and degrade gracefully.

## Testing

Vitest with `expect()` assertions and `describe`/`it` (jsdom default; Node suites use a
`// @vitest-environment node` header). Dependency-injection fakes via `vi.fn()` + local `buildDeps()`
factories instead of global fs mocks; MSW for HTTP. `async`/`await` throughout. Coverage is v8 with an
explicit include allowlist in vitest.config.ts.

Test locations:

Co-located `<module>.test.ts(x)` next to source under `src/`; shared setup in `test/setup.ts`,
scratch fixtures under `test/temp/`.

## Model routing

**Model routing is opt-in.** By default (`model_routing: session`) every dispatched subagent runs on the user-selected
session model - the same rule as the main-thread inline skills. A project opts into cost routing by choosing a
strategy at setup; only then do the sections below apply.

Each value names a **model capability**, not a specific model - map it to the best-matching model your platform offers:
**cheap** (fastest/lowest-cost; mechanical single-file work + verification), **standard** (default; multi-file
integration and judgment), **most capable** (highest-capability; architecture and complex reasoning).

When routing is enabled, the table has two sections per profile: **Implementation (per triage)** drives `execute-task`
by triage level; **Review & verification (per worker)** drives the fixed-role `verify-task` and `pr-review`;
`requirement-analysis` is pinned to **most capable** (planning is the highest-leverage phase). Main-thread inline
skills always run on the user-selected session model.

No routing - all dispatched subagents run on the user-selected session model.

## Project-specific constraints

- Package manager is Bun - use `bun`, not `npm` (bun.lock; CI uses `bun install --frozen-lockfile`).
- Generated assets, sourcemaps, prerendered HTML, and cache-busting hashes must be deterministic across
  Windows/WSL/Ubuntu - normalize text to LF before hashing/embedding/writing (`src/text-normalization.ts`);
  preserve binary bytes unchanged.
- Frontend/layout changes must support both LTR and RTL (logical CSS properties, `$rtl-sign`, `rtl()`).
- PageSpeed Insights, accessibility, and print output/workflows are first-class requirements for frontend changes.
- Maintain highest-possible Vitest coverage - add matching tests for every logic change (coverage.include allowlist in vitest.config.ts).
- Publishing is tag-driven: pushing a `vX.Y.Z` tag runs the GitHub Actions npm publish (OIDC provenance); package.json version must match the tag.
